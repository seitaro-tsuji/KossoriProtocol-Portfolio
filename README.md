## ゲーム概要
2D見下ろし型のステルスゲームです。

プレイヤーは、マップ内にランダムに配置された敵の視界を避けながらゴールを目指します。敵に接触したり、一定の条件で視界に捉えられたりするとゲームオーバーになります。

マップ内には移動速度を上げるアイテムや、すべての敵を一時的に停止させるアイテムが配置されており、これらを活用してゴールを目指します。

クリアタイムが記録されるため、より短い時間でのクリアを目指して繰り返し挑戦できるゲームです。

## 操作方法
### キーボード・マウス
- **WASD / 方向キー**：移動
- **Shiftキー**：ダッシュ
- **Enter**：ゲームスタート・リスタート
- **Escape**：タイトルに戻る

「ゲームスタート」や「タイトルに戻る」などは、ゲーム内に配置されたボタンをクリックすることでも可能です。

## 工夫した点
### 開発方針
制作期間が2日間と限られていたため、素材選定の時間を削減できるよう、Unityの標準的な図形を中心に使用しました。

また、「ゲームとして最低限成立する作品」をまず完成させ、残った時間で要素を追加していくという実装順を意識しました。

さらに、タイム短縮を目指して短いスパンで繰り返しプレイするゲームになるため、ゲーム終了から再スタートまでの時間をなるべく短くし、プレイする人がリプレイ時にストレスを感じないようにしました。

### 最低限の完成ライン
- タイトル→インゲーム→リザルトの一連のゲームループの完成
- インゲーム内から直接リスタートできる機能
- 敵キャラクターの配置・移動・視点変更
- 敵に見つかったときのゲーム失敗の処理

### 追加で実装できた内容
- スピードアップアイテム・スタンアイテムの実装
- マップ・敵・アイテムのランダム生成
- サウンドの実装やアイテム取得時のテキスト演出
- 連続クリア時のリザルト表記
- ダッシュ中に敵に気づかれやすくなる仕様の追加

## 反省点
### ゲームデザインの面の反省点
短い制作期間で「何度も繰り返し遊べるゲーム」を目指したため、マップの形や敵・アイテムの配置などを全てランダム生成にした結果、プレイするたびに難易度が大きく変化するようになりました。
クリアタイムの短縮を目的に何度もプレイする場合、必要以上に運要素を含んでしまう点は今回の最大の反省点だと感じています。

### 実装面の反省点
開発時間を短縮するため、今回のソースコードでは`IngameManager`、`SceneChanger`、`AudioManager`と、シングルトンを多用しています。2日間の開発では特に問題は発生しませんでしたが、長期の開発を考慮する場合、クラス設計や役割分担を徹底するべきだと思っています。

また、`EnemyManager`、`ItemGenerator`ではあらかじめ決められた配置候補地点からランダムで選択して敵・アイテムを配置していますが、配置数が候補地点数を超えている場合の処理を省略しているため、堅牢性の面で課題があります。
